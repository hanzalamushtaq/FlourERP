# Plan: Phase 5 Gundam Pisai (Grinding) Module

## Goal
Implement the dedicated Pisai grinding service module with dual service options (*Safai + Pisai* vs *Pisai Only*), direct fee entry/override, independent 4-digit monotonic token sequencing (`0001`–`9999`), large-format thermal ticket printing, and RBAC-gated discount/credit assignment.

## Requirements
- `PISAI-01`: Dedicated high-speed Pisai billing screen capturing customer name and wheat weight in KG.
- `PISAI-02`: Dual service selection (*Safai + Pisai* vs *Pisai Only*) with direct manual fee override.
- `PISAI-03`: Independent, non-resetting monotonic 4-digit sequential token sequence (`0001`–`9999`) across days with database row locking.
- `PISAI-04`: Large-format thermal print ticket emphasizing the 4-digit token for customer pickup.
- `PISAI-05`: RBAC-gated discounts (`can_discount`) and credit issuance (`can_issue_credit`).

## Architecture & Implementation Details
1. **Prisma Schema (`apps/api/prisma/schema.prisma`)**:
   - `PisaiRecord` model:
     - `id` (UUID PK)
     - `tokenNumber` (Int, unique monotonic counter)
     - `tokenFormatted` (String, 4-digit padded e.g. "0101")
     - `serviceType` (Enum: `SAFAI_PISAI`, `PISAI_ONLY`)
     - `weightKg` (Float)
     - `ratePerKg` (Float)
     - `feeAmount` (Float)
     - `discount` (Float)
     - `netTotal` (Float)
     - `receivedAmount` (Float)
     - `paymentMethod` (Enum: `CASH`, `CREDIT`)
     - `customerId`, `customerName`, `customerPhone`
     - `billerId` (FK to User)
     - `printPayload` (Text/Hex formatted thermal ticket)
   - Seeded `bill_sequences` with `name = "PISAI_TOKEN"` starting counter.

2. **Backend Express Routes (`apps/api/src/routes/pisai.routes.ts`)**:
   - `POST /api/pisai`:
     - Transactional row-locking on `billSequence` table (`PISAI_TOKEN`).
     - Monotonic 4-digit sequence format: `String(seq.currentVal).padStart(4, '0')`.
     - RBAC check: disallows positive discount unless user has `can_discount` or `SuperAdmin`.
     - RBAC check: disallows credit sale unless user has `can_issue_credit` or `SuperAdmin`.
     - Generates thermal print payload formatted for 80mm/58mm printers with giant token banner.
     - Logs `CREATE_PISAI_TICKET` in audit trail.
   - `GET /api/pisai`: Paginated listing with date and customer query filters.
   - `GET /api/pisai/:id/reprint`: Retrieves unchanged original thermal ticket payload for exact customer reprints.

3. **Frontend Screen (`apps/web/components/billing/PisaiBillingScreen.tsx`)**:
   - Visual dual-service toggle cards with custom SVG chakki/flour graphics.
   - Numeric keypads and inputs with keyboard shortcuts.
   - Direct manual fee override with auto-calculation fallback.
   - RBAC-aware discount toggle (visible/allowed only with `can_discount`).
   - Customer search autocomplete wired to `GET /api/customers/search`.
   - Real-time token display badge (`#0101`) updated from server on mount and incremented on submission.
   - Dynamic large thermal ticket modal (`ReceiptPreviewModal`).
