# Plan 02-02: Authentication Engine, Session Management & PIN-Lock API

## Objective
Implement secure authentication for counter staff and shop owners using bcrypt password hashing, persistent session management, and a dedicated 4-digit PIN verification API for the idle screen lock overlay.

## Requirements Addressed
- **AUTH-01**: User authentication via username and password with bcrypt hashing and session-based persistent login.
- **AUTH-02**: Idle-timeout PIN-lock verification endpoint that authenticates the locked user's 4-digit PIN without invalidating the active session.

## Tasks
1. **Password & PIN Hashing Utilities**:
   - Secure bcrypt wrapper for password hashing (cost factor 10-12).
   - 4-digit numeric PIN hashing and comparison routines.
2. **Session / Token Management**:
   - Session store or HTTP-only signed cookies / JWT bearer authentication.
   - Authentication middleware (`requireAuth`) validating active session and attaching current user & permissions to `req.user`.
3. **Authentication Endpoints**:
   - `POST /api/auth/login`: Authenticate with `username` and `password`, return user profile with assigned permissions.
   - `POST /api/auth/logout`: Destroy session / revoke tokens.
   - `GET /api/auth/me`: Return current user info, active role, and permission array for frontend hydration.
   - `POST /api/auth/verify-pin`: Authenticate 4-digit PIN for currently logged-in user to unlock PIN-lock overlay without full re-login.
4. **Initial User & Role Seeder**:
   - Automated seed script generating default `SuperAdmin` role and initial shop owner user (`hanzala`, default PIN `1234`).
   - Default `Biller` role with counter billing permissions.

## Verification
- Test `POST /api/auth/login` with correct credentials -> 200 OK + session established.
- Test `GET /api/auth/me` with session -> returns user profile and permissions.
- Test `POST /api/auth/verify-pin` with valid PIN -> 200 OK `{"unlocked": true}`; test with invalid PIN -> 401 Unauthorized.
- Test `POST /api/auth/logout` -> terminates session, subsequent requests return 401.
