# Plan 02-03: Dynamic RBAC Engine & Fine-Grained Permission Middleware

## Objective
Build a dynamic Role-Based Access Control (RBAC) engine with fine-grained permission enforcement middleware, custom role management endpoints, and dynamic frontend navigation integration.

## Requirements Addressed
- **RBAC-01**: Dynamic role-based access control allowing custom roles with granular permission assignments.
- **RBAC-02**: Granular permission middleware on backend API endpoints, and dynamic client-side role and permission connectivity.

## Tasks
1. **Granular Permissions Catalog**:
   - Seed and maintain complete permissions catalog:
     - `can_bill` (create standard product bills)
     - `can_pisai` (generate grinding tokens)
     - `can_discount` (apply discretionary manual discounts)
     - `can_manage_prices` (update daily rates)
     - `can_issue_credit` (assign udhaar to customers)
     - `can_view_reports` (view revenue, ledger, and cash positions)
     - `can_void_bills` (void bills and reversal transactions)
     - `can_close_day` (trigger day-end closing & z-report)
     - `can_manage_users` (create users and assign roles)
2. **Permission Guard Middleware**:
   - `requirePermission(code: string)` higher-order Express middleware.
   - Verify that `req.user.permissions` contains the requested permission code.
   - Return structured 403 Forbidden error response `{"error": "PERMISSION_DENIED", "requiredPermission": code}` when unauthorized.
3. **Role & Permission Management API**:
   - `GET /api/roles`: List all roles with attached permission codes.
   - `POST /api/roles`: Create new custom role with assigned permission codes (Admin only).
   - `PUT /api/roles/:id`: Update role permissions and description (Admin only).
   - `GET /api/permissions`: List all available system permission definitions.
4. **Frontend Dynamic Permission Integration**:
   - Integrate `apps/web` Auth context / hook with `/api/auth/me`.
   - Conditionally render or disable restricted actions (e.g. discount inputs, admin tabs, price editing modal) based on current user's granted permissions.

## Verification
- Call a protected endpoint without permission -> 403 Forbidden with `PERMISSION_DENIED`.
- Call with valid permission -> 200 OK.
- Create a custom role via `POST /api/roles`, assign it to a test user, and verify updated access rights immediately take effect.
- Verify frontend hides/disables Admin tabs and discount toggles when logged in as a restricted Biller.
